# GPT-Live voice architecture

The independent FlowPath news app owns its local `lib/gpt-live/{protocol,backend,runtime,browser,idle}.ts` implementation. Its build and tests do not require a sibling Studio checkout or byte-identical files in another application. Studio's former shared implementation is historical context; the news app's voice runtime and app-specific tool adapters can evolve independently.

## Shared path

Browser microphone and speaker → audio-only WebRTC → GPT-Live-1 (Marin). The application server creates the session with `POST /v1/live/sessions`, reads the JSON session ID and SDP answer, and attaches to `/v1/live/sessions/{id}/attach`. The browser has no provider command channel or provider credentials. Browser media readiness precedes the opening message. ICE gathering completes before the offer is submitted.

GPT-Live uses client delegation. The server accumulates exact timestamped transcript fragments and supplies those plus current validated application state to GPT-6 Luna Fast through Responses with `service_tier: "priority"` and low reasoning. This text model also handles FlowPath curation and research; GPT-Live remains the audio transport. Delegation events carry an opaque ID, not task text. Transcript gaps do not trigger tools or cancel jobs. A new delegation or explicit manual change invalidates pending results; ordinary backchannels do not cancel backend work. Context is ephemeral and bounded. The common backend has no automatic retries or parallel tools and permits at most four tool rounds followed by one tool-free response; Studio selects a stricter one-tool limit. Initial output is capped at 1,200 tokens and continuations at 500. Each delegated job has a 35-second deadline.

Only app adapters execute tools. Studio validates published references and waits for browser acknowledgments for plans, navigation and external search views. FlowPath retains its news attribution, story selection, path, research and screen handlers. Large catalogs and research stay in backend context. Speakable results return through `session.commentary.append`; context and application instructions use their separate append events. Every append is conservatively bounded to at most 480 UTF-8 bytes, below the 500-token API ceiling.

Story opening supplies the existing summary, significance, and grouped reporting immediately. Its single Luna stream publishes a whole checked research snapshot to backend context and OpenUI together, while map generation continues. One concise research continuation waits for quiet input/output and an idle backend. User speech, a newer delegation, manual navigation, story changes, and closing cancel automatic continuation; available context still updates silently. Final map completion does not automatically enumerate paths. Only saved map IDs become actionable, and a failed map retains already published research. Cached maps may arrive directly without an intermediate research stage.

Research prose is retained in full in snapshots and backend reasoning context. Expandable UI previews abbreviate only presentation. For automatic speech, complete selected facts, their sources, and uncertainty are sent as bounded thinking chunks before a short commentary cue asks Live for a brief qualified summary. Chunking happens before the runtime's general append limit, so long facts keep their closing qualifications without another model request.

Above the possibility cards, a subtle voice hint suggests saying “talk me through these options”; there are no dedicated walkthrough buttons. The `start_walkthrough` voice tool starts a bounded queue of existing saved choices; `stop_walkthrough` stops it. Each step waits for the browser to confirm that its highlighted, expanded card is visible, then supplies only that card's summary, assumption, and first watch signal to Live. It makes no additional Responses or research calls. New speech, delegation, manual navigation, hidden pages, or session closure cancel the queue; broad what-if questions can still create conversation analysis without selecting a saved branch. Once per selected story, an optional invitation waits for introduction playback to become quiet and is discarded if the user takes the conversation elsewhere.

GPT-Live has no per-response speech-finished event. The guide therefore requires the expected option/title and spoken ending in the assistant transcript, observed output activity followed by browser media quiet, and a further 400 ms cancellable gap. Neither provider response/append events nor transcript delivery alone advance it. A missing or paraphrased ending pauses the guide after 45 seconds without retrying; its current card remains discussable. On interruption or a manual action during the guide, the client mutes stale output until the observed media is quiet while leaving microphone capture and the voice session connected. Fixture tests verify queue/DOM/media coordination; actual pronunciation, paraphrasing and device playback still require an explicitly authorized live test.

## Audio and lifecycle

Input, output and backend activity remain independent. Waveforms and startup protection use browser media levels, not transcript arrivals, backend completion or append acknowledgments. Both apps keep original microphone capture running and mute cloned outgoing tracks during the iOS opening protection. Protection ends two seconds after first observed output activity, with a ten-second no-output escape. Microphone initialization and acoustic echo cancellation still belong to the browser.

Output quiet uses a 1.2-second observation window. This is a UI heuristic, not proof a sentence finished or that a user heard it. FlowPath uses it to advance its per-card briefing. The opening waits for the completed catalog, publishes all cards together, and waits for the browser to confirm that the matching full catalog is rendered and its first card is visible before the first automatic sentence. Partial catalogs cannot start the opening. `catalogPending` protects this bounded preparation independently of the user-facing loading state; completion, cancellation and shutdown clear it. User speech stops automatic progression; long within-sentence pauses may need real-device tuning. Studio does not put generated assistant transcripts into cross-mode history as fully heard answers. User caption grouping is revisable; the backend keeps original fragments during the active session.

End requests `session.close`, keeps the sideband receiver alive, and awaits `session.closed` before releasing resources. A bounded timeout retains the latest duration as unconfirmed and invokes the hangup fallback. A successful HTTP hangup is not proof of final usage. Session duration snapshots are cumulative, never summed; backend token usage is separate. Existing app session-duration limits remain: Studio 120 seconds; FlowPath 600 seconds locally or 270 seconds on its hosted transport. These app limits do not create different voice quality tiers.

Both apps also use the shared inactivity policy. A session stays open while visitor input, assistant playback or backend work is active; after the configured quiet period the browser and server close the Live session. Studio publishers choose 30 seconds, one minute, two minutes or Never, with one minute as the default. FlowPath keeps its existing 45-second boundary. The server remains authoritative so a backgrounded tab cannot leave a silent session charging. Tapping the waveform after an inactivity close starts a new session with the current bounded context.

## Publisher defaults and compatibility

Every new Studio publisher defaults to voice using GPT-Live. Both legacy saved Standard and Premium values resolve to GPT-Live-1; their obsolete quality picker has been removed. Publisher tone, content, greeting and voice/chat choices remain configurable. The legacy recorded-turn provider returns 410 and asks callers to reconnect using the continuous session endpoint. The offline publisher preview remains deterministic and does not call a provider.

Studio's **End voice after inactivity** setting defaults to one minute and is persisted with the published visitor configuration. Existing saved settings without the field resolve to that default when read. `Never` is available for publishers who want the existing hard session cap to remain the only automatic boundary.

Studio's daily voice allowance now bounds session starts/openings and delegated backend tasks, not individual sentences spoken by the continuous frontend. Independent hard session limits bound voice duration, including small talk and silence. Live duration and Luna token observations are operational measurements; they are not Stripe charges or reconciled monetary balances. The synthetic billing ledger and Stripe test controls remain separate and do not authorize live AI calls.

## Verification boundary

Offline unit and browser tests use synthetic data, provider events and audio levels. They validate request schemas, tool limits, cancellation, publication boundaries, readiness and close handling. They do not establish model quality, provider account access, audio-only SDP interoperability, production hosting lifetime, or an iPhone echo fix. Those require a separately authorized live test. No deployment or live API call is part of this migration.
